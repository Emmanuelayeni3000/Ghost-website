# ghost-web

The landing page for [Ghost](https://github.com/your-org/ghost), and where the
Windows installer is served from.

```bash
npm run dev     # http://localhost:3000
npm run build
npm run lint
```

## Publishing a new build

The page serves the installer as a static file out of `public/`. After cutting a
release of the desktop app:

1. Build the installer in the `Ghost` project:

   ```bash
   cd ../Ghost
   npm run bundle
   ```

   The artifact lands at
   `src-tauri/target/release/bundle/nsis/Ghost_<version>_x64-setup.exe`.

2. Copy it into `public/`:

   ```bash
   cp ../Ghost/src-tauri/target/release/bundle/nsis/Ghost_0.1.0_x64-setup.exe public/
   ```

3. Update `DOWNLOAD` in [`app/content.ts`](app/content.ts) — `version`,
   `filename`, `href`, and `size`. The filename in that file **must** match the
   file in `public/`, or the download button 404s. There is no build-time check
   for this; it is the one thing to get right by hand.

Installers are not committed. `public/*.exe` is gitignored — a repository is the
wrong place for a 9 MB binary that changes every release, and hosting that
publishes from git will pick the file up from the release artifact instead.

## Design

The page is a datasheet, not a brochure: hairline rules instead of cards,
monospace labels carrying the structure, and figures presented as instrument
readouts. It shares the application's palette exactly, so the page and the thing
it installs read as one product.

Every number on the page is one the software actually produces. A page quoting
latencies the product does not hit is the fastest way to make the rest of it
untrustworthy — so if a figure changes in the app, it changes in
`app/content.ts` too, or it comes out.

The claims about privacy and the invisible overlay are deliberately hedged where
the underlying mechanism is hedged. Microsoft describes content protection as
offering no guarantee, so the page says so rather than promising invisibility.

## Notes

- Next.js 16 App Router. `AGENTS.md` is generated by `next dev`; read
  `node_modules/next/dist/docs/` before assuming an API, since this version
  differs from older ones in ways that are easy to get wrong.
- The page is dark-only by design and declares `color-scheme: dark`.
- The overlay screenshot in the hero is rebuilt in markup rather than shipped as
  an image, so it stays sharp at any density and cannot silently drift out of
  date the way a PNG taken once does.
